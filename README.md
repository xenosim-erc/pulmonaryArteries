# pulmonaryArteries

OpenFOAM/solids4foam simulation cases and supporting tools for modelling
haemodynamics in the pulmonary arteries, using coupled fluid-structure
interaction (FSI) between healthy and pulmonary arterial hypertension (PAH)
geometries, across human and porcine anatomies.

## Repository layout

### Simulation cases

- **`humanPulmonaryArteriesFSI/`** — FSI case for human pulmonary arteries.
  Conformal fluid and solid meshes (~100,000 cells each), the solid wall
  generated by extruding the fluid domain 5% of the artery diameter, a
  neo-Hookean solid, and a laminar non-Newtonian fluid. Runs in parallel via
  `solids4Foam`; see `run.slurm`.
- **`porcinePulmonaryArteriesFSI/`** — Equivalent FSI case for porcine
  pulmonary arteries, same meshing and modelling approach.

Each case directory follows standard OpenFOAM structure (`0/`, `constant/`,
`system/`, `Allrun`) plus a Slurm submission script (`run.slurm`) for cluster
use. The FSI cases each include a `caseExplainer` file summarising the setup.

### Meshing and case-generation workflow

- **`fsiScript/`** — End-to-end workflow that turns an artery STL surface
  into a runnable FSI case: extracts centerlines, estimates a
  diameter-dependent wall thickness, generates fluid and solid meshes, and
  assembles a `templateCase`. See `fsiScript/README.md` for setup and usage.

### OpenFOAM utilities

- **`mapExtrudeDistance/`** — Maps a scalar field (e.g. wall thickness) from
  a legacy ASCII VTK surface onto an OpenFOAM boundary patch, for use as the
  distance field consumed by `varExtrudeMesh`. See
  `mapExtrudeDistance/README.md`.
- **`varExtrudeMesh/`** — Extrudes a mesh patch by a spatially varying
  distance (read from a point field), used to generate the variable-thickness
  solid wall around the fluid domain in the FSI cases. See
  `varExtrudeMesh/README`.


## Requirements

- An OpenFOAM installation (tested with OpenFOAM v2412) and
  [solids4foam](https://solids4foam.github.io) for the FSI cases, sourced
  before running `Allwmake` or any case.
- PETSc (`PETSC_DIR` set) for FSI cases using the Robin-Neumann coupling
  formulation.
- [cfMesh](https://cfmesh.com/) for the fsiScript meshing workflow.
- Internet access the first time `Allwmake` is run, to download Miniforge and
  the fsi-env conda packages (VMTK/VTK/ITK).

## Quick start

With a working OpenFOAM and solids4foam environment sourced, from this
directory:

```bash
./Allwmake
```

This builds `mapExtrudeDistance` and `varExtrudeMesh` with `wmake`, and
provisions the fsiScript Python/VMTK environment (installing a local
Miniforge to `fsiScript/.env/miniforge3` and creating the `fsi-env` conda
environment from `fsiScript/environment.yml`, if not already present). It
does not install OpenFOAM, solids4foam, or cfMesh — see `fsiScript/README.md`
for details on the fsi-env environment it creates.
